# Repo Trace

Studio G tool, one of the Repo tools (with Repo Atlas; "Repo" is the suite, 23 Nov 2026): a local API's calls, live: the developer starts their API as usual with `repo-trace` in front (`repo-trace npm run dev`, `repo-trace ./dev.sh`, or a `dev:trace` script), and Repo Trace reads what it prints. Local only (24 Nov 2026): no production, no `wrangler tail`, no Cloudflare sign-in. It never starts anything from the page (25 Nov 2026: no project picker, no Run it, no Output page): the command runs in the developer's terminal. Owner: Alex. English only. Separate from Repo Atlas on purpose (23 Nov 2026): Atlas maps the code, Trace shows what ran; a link between the two may come later (a call names the file it ran in). Decisions and backlog live in Notion (Studio G › Repo trace). The command is `repo-trace`, like the package (26 Nov 2026: renamed from `trace`, which macOS's own /usr/bin/trace shadowed).

## Layout
- `bin/trace.mjs`: the command. `repo-trace <command…>` runs it with the terminal's stdin, copies its output unchanged (trace lines left out unless `--show`), sets `TRACE=1`, and exits with it. Also `repo-trace dev` (wrangler dev with `--var TRACE:1`), `repo-trace -- <command…>`, stdin, `demo`; with nothing, the help. Options go before the command. The project for routes is the Worker in the current folder, else the one below it, named from its git repo (`learn-fm/api`).
- `src/projects.mjs`: projects (a Wrangler config up to two folders down, with a `main`), most recently changed first, each with its folder as its id; whether its code logs Repo Trace's lines (`readProject`, `logs`); their routes read from the code with patterns (pathname checks, segments from `pathname.split('/')`, `method !==` refusals, routers, switch cases), with file and line.
- `src/parse.mjs`: printed lines → events (`parseLine`), the terminal copy without trace lines (`passThrough`, `--show` keeps them), the line splitter, `fromWranglerLine` (wrangler dev's own request lines become requests, so a project needs no change).
- `src/server.mjs`: the viewer page, `/events` (server-sent events: what this run watches, then the calls) and `/api/routes`. It starts nothing. Listens on 127.0.0.1 only; `/api` requests need the `x-repo-trace: 1` header, the page's own origin and a localhost Host. Keeps the last 20,000 events for a page opened late.
- `src/demo.mjs`: a sample API (its routes, `DEMO_ROUTES`) with traffic shaped like learn.fm: requests (a 404 now and then, a rare 500), episodes being made, a few minutes of history so the pulse isn't empty.
- `viewer/index.html`: the whole viewer, one file, no build, no framework. State is reduced from events in the page. The running view is V3 (25 Nov 2026, mocks: the V3 boards on the canvas): a sidebar with the project and what's being watched ("Watching npm run dev") and three pages. **Calls** (home): every call, newest on top (requests, and groups the app logs such as an episode), filtered by path, status (All, 2xx, 4xx, 5xx) or route; a row opens in place to its waterfall and the selected step, and an open row keeps its place on screen while calls arrive above it. **Routes**: the routes read from the code as a tree, with methods and call counts, median, last status and file:line; a route opens Calls filtered to it. **Errors**: calls that answered 5xx or failed, and outgoing calls that failed inside a call that still answered, the same error grouped. Cost shows only where the app logs `usd`. Errors show the failing call's note and the route's file:line; pairing them with wrangler's own exception lines is still to do.
- `lib/trace.ts`: what an app copies in to log calls (`span`, `traceGroup`, `tracedFetch`, `traceOn`).
- `docs/format.md`: the line format. Change it there first; keep `lib/trace.ts`, the parser and the viewer in step.

## Rules
- No dependencies, no build step. Node 20+.
- Studio G design system: tokens copied by hand from `studio-g/design-system/tokens.json` into the viewer's `:root` (Light) and `[data-theme="dark"]` (After hours). No other hex values. Inter, no monospace except the JSON example and the Output view (a terminal's text). Square pixels mark state. One primary action per view.
- Services get tag colours (fixed for known names, by hash for others), category only. `danger` only for failures, always with words.
- Mint is the accent (25 Nov 2026, was sun since 24 Nov): Repo Trace shares Repo Atlas's signature colour, as the Repo tools. `spark-mint` for pixels, `tag-mint` for selected rows, `tag-mint-ink` for links and accent text (`--accent`). Services and methods keep tag colours as categories, never mint (POST and Apple are sun, ElevenLabs, PUT and PATCH vermilion); "Done" is ink.
- Copy: few words, verbs on buttons, no exclamation marks, no emoji, no promises of things that aren't built.
- Privacy: nothing leaves the computer. Repo Trace shows what the app logs; the docs tell apps never to log user text, prompts or keys.

## Check before saying it's done
- `npm test`
- `node bin/trace.mjs demo --open`, and look at it in both themes and on a narrow window.
